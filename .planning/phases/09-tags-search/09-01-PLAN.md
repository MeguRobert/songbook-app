<objective>
Establish the data + logic foundation for thematic tags: introduce a derived Tag value object,
extend the existing SearchService with tag aggregation/counting + multi-tag filtering + a pure
override-merge, add per-song tag-override persistence (so bundled read-only tags become editable),
and wire reactive providers so the entire app observes edited tags through a single source of truth.

Purpose: Phase 9 success criteria #1 ("songs can have multiple tags" — already true at the model
level, made editable here), the data layer behind #2 (filter by tag), #3 (tag browser with counts),
and #4 (tags editable). The 09-02 UI builds on this.

Output: Tag model, extended SearchService tag logic, LocalDataSource + TagRepository override
persistence, tag/override/count providers, an override-aware songsProvider, and unit tests.
</objective>

<task type="auto">
  <name>Task 2: Extend SearchService with tag aggregation, multi-tag filtering, override merge</name>
  <files>songbook_app/lib/domain/services/search_service.dart</files>
  <action>
KEEP the existing `search`, `filterByTag`, `getAllTags`, `_calculateMatchScore` (do not duplicate).
ADD (tag logic lives here — extends the existing tag-aware service, no new parallel service):

- `List<Tag> tagsWithCounts(List<Song> songs)`:
  - Group case-insensitively by tag (trim + lowercase for the grouping key) but DISPLAY the
    first-seen original casing (so "Luther" shows as "Luther", not "luther").
  - One `Tag(name, songCount)` per distinct key.
  - Order: songCount DESC, then name ascending (alphabetical) as the tiebreak.
  - Empty input or songs with no tags → empty list.

- `List<Song> filterByTags(List<Song> songs, Set<String> tags, {bool matchAll = true})`:
  - Empty `tags` → return `songs` unchanged.
  - Case-insensitive membership. `matchAll == true` → song must contain ALL selected tags (AND);
    `false` → song must contain ANY (OR).

- `List<Song> applyTagOverrides(List<Song> songs, Map<int, List<String>> overrides)`:
  - Pure merge. For each song, if `overrides` has an entry for `song.number`, return a
    `song.copyWith(tags: override)`; otherwise return the song unchanged.
  - Empty `overrides` → return the SAME list reference (fast path, no allocation).

Add `import '../../data/models/tag.dart';`. Keep the file free of Flutter/provider imports (pure).
  </action>
  <verify>`flutter analyze` clean. No Flutter imports added.</verify>
  <done>SearchService can count tags, filter by multiple tags (AND/OR), and merge per-song overrides — all pure + testable.</done>
</task>

<task type="auto">
  <name>Task 1: song_validator.py — rules + library API</name>
  <files>tools/song_validator.py</files>
  <action>
Pure stdlib. Define a `ValidationIssue` (severity 'error'|'warning', song number/identifier, field,
message) — a simple namedtuple or dataclass. Provide:

- `validate_song(song: dict, *, index=None) -> list[ValidationIssue]` — single-song rules:
  - `number`: present, int, > 0 (error).
  - `title`: present, non-empty str (error).
  - `originalKey`: present, str, matches `^[A-G][#b]?m?$` (error if missing; warning if present but
    unrecognized — OCR sometimes yields odd values, don't hard-fail the whole file).
  - `verses`: present, list, non-empty (error). Each verse: `number` int (error); if `hasNotation`
    true then `lines` non-empty (warning); each line `text` str (error); each chord `chord` non-empty
    str (error) and `position` int >= 0 (error), and `position` <= len(text) (warning — past-end chord).
  - `book` (optional): if present must be non-empty str (warning if empty).
  - `tags` (optional): if present must be a list of str (warning otherwise).
  - Unknown top-level keys: ignore (forward-compatible).
- `validate_songs(songs: list) -> list[ValidationIssue]` — runs validate_song over all and adds a
  cross-song rule: duplicate `number` values (error, reported once per duplicate group).
- `has_errors(issues) -> bool` helper.
Keep functions pure (no I/O) so they're trivially testable.
  </action>
  <verify>`python -c "import tools.song_validator"` style import works; no third-party imports.</verify>
  <done>Validator library encodes the schema rules with error/warning severities.</done>
</task>

<task type="auto">
  <name>Task 3: test_song_validator.py — unittest coverage</name>
  <files>tools/test_song_validator.py</files>
  <action>
stdlib `unittest`. Build minimal valid-song fixtures inline. Cover:
- A fully valid song → no errors.
- Missing number / non-int number / number<=0 → error.
- Missing/empty title → error.
- Missing originalKey → error; unrecognized key (e.g. 'H', 'Xyz') → warning (not error); 'Am'/'Bb'/'F#'
  accepted.
- Empty verses / verses not a list → error.
- Verse line text not str → error; chord with empty chord str → error; negative position → error;
  position past end of text → warning.
- Duplicate numbers across the list → exactly one duplicate error per colliding number.
- load_and_validate on a missing file and on malformed JSON → one error issue each.
- `has_errors` true/false.
Make runnable both via `python -m unittest tools.test_song_validator` and `python tools/test_song_validator.py`.
  </action>

Purpose: This is the data foundation for the configurable song view. Without the state model and persistence, the UI toggles have nothing to drive or persist.
Output: ViewConfig model, updated settings repository with global + per-song config, updated providers replacing SongViewMode, updated SongViewState with active view config tracking.
</objective>

    1. Create `songbook_app/lib/data/models/view_config.dart`:
       - Immutable class `ViewConfig` with two boolean fields: `showNotation` (default true) and `showChords` (default true). Lyrics are always present -- not a field.
       - Include `copyWith({bool? showNotation, bool? showChords})` method.
       - Add 3 static preset factories:
         - `ViewConfig.sheetMusic()` -> showNotation: true, showChords: true (full view)
         - `ViewConfig.chords()` -> showNotation: false, showChords: true (chord sheet)
         - `ViewConfig.lyricsOnly()` -> showNotation: false, showChords: false (clean lyrics)
       - Add convenience getters: `bool get isSheetMusicPreset`, `bool get isChordsPreset`, `bool get isLyricsOnlyPreset` (check if current state matches a preset).
       - Add `bool get isNotationWithoutChords` -> showNotation && !showChords (4th valid state).
       - Implement `==` operator and `hashCode` based on both fields.
       - Add `String toStorageString()` that encodes as "notation:chords" (e.g., "true:true", "false:true").
       - Add `factory ViewConfig.fromStorageString(String s)` that parses the above format, with fallback to `ViewConfig()` (all on) for invalid input.

    2. Update `songbook_app/lib/data/repositories/settings_repository.dart`:
       - Import `view_config.dart`.
       - Remove the `SongViewMode` enum entirely (it is currently defined here).
       - Remove `getViewMode()` and `setViewMode()` methods.
       - Add `ViewConfig getViewConfig()` -- reads from SharedPreferences key `view_config`, parses with `ViewConfig.fromStorageString()`.
       - Add `Future<bool> setViewConfig(ViewConfig config)` -- stores via `setStringSetting('view_config', config.toStorageString())`.
       - Add `ViewConfig? getSongViewConfig(int songNumber)` -- reads from key `song_view_config_$songNumber`, returns null if not set.
       - Add `Future<bool> setSongViewConfig(int songNumber, ViewConfig config)` -- stores per-song override.
       - Add `Future<bool> clearSongViewConfig(int songNumber)` -- removes per-song override by removing the key.
       - Keep existing `SettingsKeys` class but update: remove `viewMode` key, add `viewConfig = 'view_config'` key.
       - Keep all other existing methods unchanged (theme, transpose, showChords, fontSize).

    NOTE: The old `showChords` setting in SettingsKeys is separate from ViewConfig's showChords toggle. The old one controlled chord visibility in the chord view. Keep it for now -- Plan 02 will clean up the UI-level usage. Do NOT remove getShowChords/setShowChords yet.

<objective>
Establish the data foundation for setlists: a Setlist model (a named, ordered list of song numbers),
JSON persistence in the existing local store, and a SetlistRepository exposing the CRUD + reorder
operations the UI and playback layers build on.

Purpose: Phase 8 success criteria #1 (create a named setlist, add songs), #2 (reorder songs), and #4
(persist across restarts) — at the data layer. Criterion #3 ("next song" navigation) builds on this
model in 08-02.
Output: setlist.dart (+ generated serializer), LocalDataSource setlist storage, SetlistRepository,
and unit tests for the model and the repository.
</objective>

<task type="auto">
  <name>Task 1: Create the Setlist model</name>
  <files>songbook_app/lib/data/models/setlist.dart, songbook_app/lib/data/models/setlist.g.dart</files>
  <action>
Create `Setlist`, a JSON-serializable value object (mirroring `Favorite`'s style):
- `final String id;` — stable unique id (generated by the repository at creation time).
- `final String name;` — user-facing setlist name.
- `@JsonKey(defaultValue: []) final List<int> songNumbers;` — ordered song numbers.
- `final DateTime createdAt;`
- `final DateTime updatedAt;`
- `const Setlist({required id, required name, this.songNumbers = const [], required createdAt, required updatedAt});`
- `factory Setlist.fromJson` / `toJson` via json_annotation (`part 'setlist.g.dart';`).
- `copyWith(...)` for all fields.
- Convenience getters: `int get length => songNumbers.length;` and
  `bool get isEmpty => songNumbers.isEmpty;`.
- Equality + hashCode keyed on `id` ONLY (consistent with Song keyed on number / Favorite on
  songNumber). `toString()` for debugging.

Generate `setlist.g.dart`. Prefer `flutter pub run build_runner build --delete-conflicting-outputs`;
if build_runner is slow/unavailable, hand-write the file to match the generator output exactly
(favorite.g.dart is the template). The List<int> field deserializes as
`(json['songNumbers'] as List<dynamic>).map((e) => (e as num).toInt()).toList()` and serializes as
`instance.songNumbers`. Timestamps use `DateTime.parse(...)` / `.toIso8601String()`.
  </action>
  <verify>`flutter analyze` clean for setlist.dart/.g.dart. A round-trip `Setlist.fromJson(s.toJson())` preserves all fields.</verify>
  <done>Setlist is an immutable, JSON-serializable model identified by id.</done>
</task>

<task type="auto">
  <name>Task 3: Create SetlistRepository</name>
  <files>songbook_app/lib/data/repositories/setlist_repository.dart</files>
  <action>
Create `SetlistRepository(this._localDataSource)` wrapping LocalDataSource (mirrors FavoritesRepository):
- `List<Setlist> getSetlists()` → `_localDataSource.getSetlists()`.
- `Setlist? getById(String id)` → firstWhere with null fallback.
- `Future<Setlist> createSetlist(String name)` — generate a stable id
  (`'sl_${DateTime.now().microsecondsSinceEpoch}'`), build a Setlist with empty songs and
  createdAt==updatedAt==now, persist the appended list, return the created Setlist.
- `Future<bool> renameSetlist(String id, String newName)` — copyWith(name, updatedAt: now).
- `Future<bool> deleteSetlist(String id)` — remove by id, persist.
- `Future<bool> addSong(String id, int songNumber)` — append only if not already present
  (idempotent), bump updatedAt, persist.
- `Future<bool> removeSong(String id, int songNumber)` — remove the number, bump updatedAt, persist.
- `Future<bool> reorderSongs(String id, List<int> orderedSongNumbers)` — replace songNumbers with the
  provided order (trusting the caller's order), bump updatedAt, persist.
All mutators operate on a fresh `getSetlists()` copy, replace the target entry, and call
`saveSetlists`. Return `false` when the id is not found. Keep methods small; no exceptions thrown
(silent-fallback convention).
  </action>
  <verify>`flutter analyze` clean. Repository references getSetlists/saveSetlists.</verify>
  <done>All setlist CRUD + reorder operations available through one repository, matching project conventions.</done>
</task>

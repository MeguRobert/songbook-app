<objective>
Close the UAT Test 5 gap: text-size controls scale chord/lyric text but NOT sheet
music notation. Root cause (see debug session): per-song textScale is consumed only
by ChordView; it is never passed to the sheet music path, SheetMusicRenderer has no
scale parameter, and all notation geometry derives from a compile-time constant.

Approach (from diagnosis — vector-crisp, no EngravingConstants refactor): thread
textScale into SheetMusicRenderer; lay out at `availableWidth / textScale` (so line
wrapping matches the visible width), size the CustomPaint box by `layout.totalWidth
* textScale` × `layout.totalHeight * textScale`, and apply `canvas.scale(textScale)`
inside SheetMusicPainter.paint. This scales the whole engraving uniformly while
keeping it resolution-independent.

Purpose: Make A+/A- (and, after plan 04-05, pinch) affect the notation just like
text — a directly reported user request.
Output: Notation that grows/shrinks with textScale, wrapping preserved.

NOTE: This plan shares the sheet-music render path with plan 04-05 (pinch fix).
This plan (04-04) does the textScale plumbing + scaling; 04-05 runs AFTER it
(wave 2) and removes the gesture-stealing InteractiveViewers. Do not remove any
InteractiveViewer here — that is 04-05's job — to avoid conflicting edits.
</objective>

SheetMusicPainter (sheet_music_painter.dart):
- Add a `final double textScale;` field with default `1.0` to the constructor
  (alongside `layout`, `noteColor`, `staffColor`, `showChords`).
- At the top of `paint(Canvas canvas, Size size)` (line ~77), before any drawing:
  `canvas.save(); canvas.scale(textScale);` and add a matching `canvas.restore();`
  at the very end of the method (after all draw calls). Every existing draw call
  then renders in scaled coordinates, keeping vectors crisp.

- AVOID DOUBLE-SCALING THE HEADER CENTERING (required): `paint` calls
  `_drawHeader(canvas, size)` first (line 78). `_drawHeader` (lines 103-117) centers
  the "Key: X | Time: Y" text with `Offset((size.width - textPainter.width) / 2, 5)`.
  Once you wrap drawing in `canvas.scale(textScale)`, the `size` handed to `paint`
  is the CustomPaint box size, which the renderer now sets to
  `layout.totalWidth * textScale` (already scaled). Centering off that scaled
  `size.width` while inside the scale block scales the offset a SECOND time, pushing
  the header off-center whenever textScale != 1.0. Fix it by centering from the
  UNSCALED layout width, which is available on the painter as `layout.totalWidth`:
  change `_drawHeader` to compute the x offset as
  `(layout.totalWidth - textPainter.width) / 2` (drop the `size` dependency, or keep
  the `size` param but ignore its width). The header then centers correctly in the
  pre-scale coordinate space and the surrounding `canvas.scale(textScale)` maps it to
  the true visual center at any scale. (Confirm `layout.totalWidth` is the same value
  the renderer multiplies by textScale for the SizedBox width — it is; the renderer
  already reads `layout.totalWidth`.)

- In `shouldRepaint` (line ~949): also repaint when `oldDelegate.textScale != textScale`.

SheetMusicRenderer (sheet_music_renderer.dart):

  (line ~26) and as a field (near line ~19).
- In `didUpdateWidget` (line ~56): add `oldWidget.textScale != widget.textScale`
  to the condition that triggers `_calculateLayout()`.
- In `build` -> `LayoutBuilder` (line ~134): create the layout engine with
  `availableWidth: constraints.maxWidth / widget.textScale` instead of
  `constraints.maxWidth`. This keeps the number of measures per system correct for
  the physical width once scaled up.
- The canvas SizedBox (lines ~170-173): change to
  `width: layout.totalWidth * widget.textScale,

- Do not touch the header/footer/verse text builders — leave them at base size

In `song_provider.dart`, fix `transposeUp()` and `transposeDown()` to use a symmetric 12-semitone range of -6 to +5:

1. In `transposeUp()` (currently line 67-73):
   - Change the wrapping condition from `if (newAmount > 12) newAmount = -11;` to `if (newAmount > 5) newAmount = -6;`
   - This means pressing up from +5 wraps to -6

2. In `transposeDown()` (currently line 76-82):
   - Change the wrapping condition from `if (newAmount < -11) newAmount = 12;` to `if (newAmount < -6) newAmount = 5;`
   - This means pressing down from -6 wraps to +5

WHY -6 to +5 instead of -6 to +6: A 12-semitone cycle should cover exactly 12 values. -6 to +5 gives exactly 12 values (including 0). Going +6 and -6 would be the same pitch, so we pick one direction. Musicians transpose at most a tritone (6 semitones) in either direction.

3. In `song_view_screen.dart`, add `closeSong()` call in `dispose()` to ensure state cleanup:
   - In the `dispose()` method (currently line 36-38), add `ref.read(songViewProvider.notifier).closeSong();` BEFORE `super.dispose();`
   - This guarantees transpose state is cleared when navigating away from a song

4. IMPORTANT: Do NOT change `setTranspose(int semitones)` — it should remain unconstrained for direct key selection (dropdown style). The wrapping only applies to the increment/decrement buttons.

   ```dart
   future: _tryLoadSvg(svgPath).then((svg) {
     if (svg != null) return svg;
     return _tryLoadSvg(originalPath).then((svg) => svg ?? '');
   }),
   ```
   With a future that returns a `({String svg, bool isOriginalFallback, bool isMissing})` record:
   ```dart
   future: _loadSheetMusicWithFallback(svgPath, originalPath, targetKey, song.originalKey),
   ```

2. Create a new private method `_loadSheetMusicWithFallback`:
   ```dart
   Future<({String svg, bool isOriginalFallback})> _loadSheetMusicWithFallback(
     String transposedPath, String originalPath, String targetKey, String originalKey,
   ) async {
     // If not transposed, just try loading the original
     if (targetKey == originalKey) {
       final svg = await _tryLoadSvg(originalPath);
       return (svg: svg ?? '', isOriginalFallback: false);
     }
     // Try transposed first
     final transposedSvg = await _tryLoadSvg(transposedPath);
     if (transposedSvg != null) {
       return (svg: transposedSvg, isOriginalFallback: false);
     }
     // Fall back to original
     final originalSvg = await _tryLoadSvg(originalPath);
     if (originalSvg != null) {
       return (svg: originalSvg, isOriginalFallback: true);
     }
     // Nothing available
     return (svg: '', isOriginalFallback: false);
   }
   ```

3. Update the FutureBuilder's builder to use the record type and show distinct messages:
   - If `result.svg` is empty: call `_buildNoSheetMusic(context)` (existing — "No sheet music available for this song")
   - If `result.isOriginalFallback` is true: show an info banner ABOVE the SVG saying "Sheet music for [targetKey] not available. Showing original key ([originalKey])." then render the SVG below
   - If `result.isOriginalFallback` is false and SVG loaded: render normally (transposed SVG found)

4. Update `_buildNoSheetMusic()` to show a more specific message: "No sheet music available for this song" (keep current text, but make sure it says "for this song" to clarify it's per-song, not a transpose issue).

5. Keep the existing `_tryLoadSvg()` method unchanged — it correctly catches errors and returns null.

6. Remove the old inline fallback info banner (lines 226-247 in the current builder) since the new record-based approach handles this more cleanly.
